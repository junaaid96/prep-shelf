# C — Deep Dive & Interview Reference (2026)

**Current state (Sept 2026):** **C23** (ISO/IEC 9899:2024) is the current standard — `nullptr`, `constexpr`, `typeof`, `_BitInt(N)`, `[[attributes]]`, binary literals, `#embed`. GCC 15/Clang 20 support most of it (`-std=c23`). C remains the language of kernels, embedded firmware, runtimes, and every FFI boundary — which is exactly why interviews use it to probe whether you actually understand memory.

---

## 1. Memory layout — the diagram you must be able to draw

```
 high addresses
 ┌─────────────────────┐
 │  command-line args  │
 │  environment        │
 ├─────────────────────┤
 │  stack   ↓          │  locals, params, return addresses; auto-managed, LIFO
 │                     │
 │  (unmapped gap)     │
 │                     │
 │  heap    ↑          │  malloc/free; you own the lifetime
 ├─────────────────────┤
 │  .bss               │  uninitialised globals/statics → zeroed at load
 │  .data              │  initialised globals/statics
 │  .rodata            │  string literals, const data — read-only
 │  .text              │  machine code
 └─────────────────────┘
 low addresses
```

```c
int   g_uninit;              // .bss, zero-initialised
int   g_init = 42;           // .data
const char *msg = "hello";   // pointer in .data, "hello" itself in .rodata

void f(void) {
    int local = 1;           // stack
    static int calls = 0;    // .bss — persists across calls, scoped to f
    char *buf = malloc(64);  // heap — YOU must free it
    free(buf);
}
```

Writing through a pointer to a string literal (`char *s = "hi"; s[0] = 'H';`) is undefined behaviour and usually segfaults because `.rodata` is mapped read-only. Use `char s[] = "hi";` to get a mutable copy on the stack.

> **Asked as:** "Where does each variable live?" · "What's the difference between `.bss` and `.data`?" · "Why does modifying a string literal crash?"

## 2. Pointers, arrays, and decay

```c
int arr[5] = {1,2,3,4,5};
int *p = arr;                  // array decays to a pointer to its first element

sizeof(arr);                   // 20 — the whole array
sizeof(p);                     // 8  — just a pointer
arr[2] == *(arr + 2) == p[2] == *(2 + arr) == 2[arr];   // all the same

void takes(int a[5]) {         // LIE: the parameter is really `int *a`
    sizeof(a);                 // 8, not 20 — pass the length explicitly
}
void better(const int *a, size_t n);
```

**Pointer arithmetic scales by the pointed-to type.** `p + 1` advances `sizeof(int)` bytes.

```c
// const placement — read right to left
const char *p;          // pointer to const char   — can't do *p = 'x'
char * const p;         // const pointer to char   — can't do p = other
const char * const p;   // both
```

Double pointers show up whenever a function must modify the caller's pointer:

```c
int alloc_buffer(char **out, size_t n) {
    char *tmp = malloc(n);
    if (!tmp) return -1;
    *out = tmp;                 // writes through to the caller's variable
    return 0;
}
char *buf = NULL;
if (alloc_buffer(&buf, 128) == 0) { /* use buf */ free(buf); }
```

> **Asked as:** "Why does `sizeof` differ inside a function?" · "Explain `const char *` vs `char * const`." · "Why does swapping need `int **`?"

## 3. Dynamic memory: the five bugs everyone writes once

```c
char *s = malloc(n);               // 1. NOT checking for NULL
if (!s) return -1;

memcpy(s, src, n);                 // 2. off-by-one: forgetting the '\0' → use n+1 for strings
free(s);
s = NULL;                          // 3. use-after-free / double-free → null it after freeing

// 4. Leak: reassigning before freeing
char *t = malloc(10);
t = malloc(20);                    // first block leaked

// 5. realloc losing the original on failure
char *tmp = realloc(t, 40);
if (!tmp) { free(t); return -1; }  // WRONG to write `t = realloc(t, 40)` — on failure t is lost
t = tmp;
```

`malloc` (uninitialised) vs `calloc` (zeroed, and it checks `count * size` for overflow) vs `realloc` (may move the block — every old pointer into it is invalid) vs `free`.

**Tooling is not optional:**

```bash
gcc -std=c23 -Wall -Wextra -Wpedantic -Wshadow -Wconversion -g -O1 \
    -fsanitize=address,undefined -fno-omit-frame-pointer main.c -o app
valgrind --leak-check=full --track-origins=yes ./app
```

ASan/UBSan catch use-after-free, overflow, and UB at runtime with roughly 2× slowdown — run your whole test suite under them in CI.

> **Asked as:** "malloc vs calloc." · "What does `realloc` do on failure?" · "How do you find a memory leak in C?" · "What is a dangling pointer?"

## 4. Undefined behaviour — the thing that makes C hard

UB means the compiler may assume it never happens and optimise accordingly. The result isn't "some garbage value"; it's code deletion and time-travel bugs.

```c
// Signed overflow is UB → the compiler can assume x+1 > x always
int f(int x) { return x + 1 > x; }        // compiles to `return 1;`

// Null check after dereference is dead code to the optimiser
void g(struct S *s) {
    int v = s->field;      // dereference implies s != NULL
    if (!s) return;        // ← the compiler DELETES this
}

// Strict aliasing: accessing an object through an incompatible type
float bits_to_float(uint32_t u) {
    // return *(float*)&u;              // UB
    float f; memcpy(&f, &u, sizeof f);  // correct, and optimises to the same instruction
    return f;
}
```

Other frequent UB: reading uninitialised memory, out-of-bounds access, shifting by ≥ width (`1 << 32`), unsequenced modification (`i = i++`), returning a pointer to a local, `%d` with a `long` in `printf`.

> **Asked as:** "What is undefined behaviour and why is it worse than a wrong answer?" · "Explain strict aliasing." · "Is `i = i++` defined?"

## 5. Strings and safe buffer handling

C strings are NUL-terminated `char` arrays. Every string function is a potential overflow.

```c
char dst[8];
strcpy(dst, src);                   // ✗ unbounded — the classic stack smash
strncpy(dst, src, sizeof dst);      // ✗ may not NUL-terminate!
snprintf(dst, sizeof dst, "%s", src);   // ✓ always terminates, returns needed length

// Safe append with explicit truncation detection
int n = snprintf(dst, sizeof dst, "%s/%s", dir, file);
if (n < 0 || (size_t)n >= sizeof dst) return -1;   // truncated
```

Prefer `snprintf`, `strnlen`, and length-carrying structs over bare `char *`:

```c
typedef struct { const char *data; size_t len; } str_view;   // no allocation, no terminator games
```

`strlen` is O(n) — never call it inside a loop condition over the same string.

> **Asked as:** "Why is `strcpy` dangerous?" · "What's wrong with `strncpy`?" · "How would you write a safe string concat?"

## 6. Structs, alignment, and padding

```c
struct Bad  { char a; int b; char c; };    // 12 bytes: 1 + 3 pad + 4 + 1 + 3 pad
struct Good { int b; char a; char c; };    //  8 bytes: 4 + 1 + 1 + 2 pad

_Static_assert(sizeof(struct Good) == 8, "layout changed");
```

Order members **largest-to-smallest** to minimise padding — in a struct you allocate a million of, this is real memory. Never `memcmp` two structs to compare them: padding bytes are indeterminate. Never write a struct to disk/network directly: padding, endianness, and type sizes differ across platforms — serialise field by field.

Bit fields and unions:

```c
union Reg { uint32_t raw; struct { uint32_t enable:1, mode:3, reserved:28; } bits; };
```

Type punning through a union is *defined* in C (unlike C++), which is why embedded code uses it.

> **Asked as:** "Why is `sizeof` this struct 12 and not 6?" · "How do you reduce struct size?" · "Struct vs union."

## 7. Compilation model and the preprocessor

**Preprocess → compile → assemble → link.**

```bash
gcc -E main.c -o main.i     # preprocessed source (macros expanded, headers inlined)
gcc -S main.i -o main.s     # assembly
gcc -c main.s -o main.o     # object file
gcc main.o util.o -o app -lm   # link
```

- `#include <x.h>` searches system paths; `"x.h"` searches the local directory first.
- Header guards (`#ifndef X_H`) or `#pragma once` prevent double inclusion.
- `static` at file scope = internal linkage (invisible to the linker) — this is how you keep helpers private.
- `extern` declares without defining — globals get `extern` in the header, a definition in exactly one `.c`.
- `inline` is a hint plus a linkage rule, not a guarantee.

Macro hygiene:

```c
#define SQUARE(x) ((x) * (x))     // parentheses everywhere
SQUARE(a + b);                    // without them → a + b*a + b
#define MAX(a,b) ((a) > (b) ? (a) : (b))
MAX(i++, j);                      // still buggy — double evaluation. Prefer static inline functions.
```

**"Undefined reference to ..."** = linker error (declared but never defined, or the `.o`/`-l` library is missing). **"Undefined symbol at runtime"** = missing shared library — check `ldd`.

> **Asked as:** "Walk through the compilation stages." · "What does `static` mean at file scope vs inside a function?" · "Difference between a declaration and a definition?" · "Why do macros need so many parentheses?"

## 8. A worked example: a growable dynamic array

```c
#include <stdlib.h>
#include <string.h>

typedef struct { int *data; size_t len, cap; } vec;

int vec_push(vec *v, int value) {
    if (v->len == v->cap) {
        size_t new_cap = v->cap ? v->cap * 2 : 8;          // amortised O(1)
        if (new_cap > SIZE_MAX / sizeof(int)) return -1;   // overflow guard
        int *tmp = realloc(v->data, new_cap * sizeof(int));
        if (!tmp) return -1;                               // v->data still valid
        v->data = tmp;
        v->cap  = new_cap;
    }
    v->data[v->len++] = value;
    return 0;
}

void vec_free(vec *v) { free(v->data); v->data = NULL; v->len = v->cap = 0; }
```

Doubling gives amortised O(1) push: n pushes cost 1+2+4+…+n < 2n copies total.

> **Asked as:** "Implement a dynamic array." · "Why double the capacity instead of adding a fixed amount?"

## 9. Rapid-fire answers

| Question | Answer |
|---|---|
| `NULL` vs `nullptr` (C23) | `nullptr` is a typed null pointer constant — no more `(void*)0` ambiguity in varargs |
| Stack vs heap | Automatic LIFO, fast, small, freed on return vs manual, large, fragmentable |
| `sizeof(char)` | Always 1 by definition; `CHAR_BIT` is usually but not necessarily 8 |
| `volatile` | Tells the compiler the value can change outside program flow (MMIO, signal handler) — **not** a threading primitive; use `_Atomic` / C11 atomics |
| `restrict` | Promise that a pointer is the only access path to that object — enables big optimisations |
| Function pointer | `int (*cmp)(const void*, const void*)` — the basis of `qsort` and vtables in C |
| `static` inside a function | One instance, lifetime of the program, scope of the block |
| Passing an array | Always decays to a pointer — pass the length too |
| Endianness | Byte order in memory; use `htonl`/`ntohl` on the wire |
| `int` size | Implementation-defined; use `<stdint.h>` (`int32_t`, `uint64_t`) when width matters |
